API Key Guide

Steal An Egg backend — buyer authentication and read-only API reference.

1. What is a Buyer API Key?

A buyer API key authenticates requests to protected buyer endpoints. Enter your key only into a trusted frontend or tool that you control.

Security: Never share your API key publicly, post it in Discord, or include it in screenshots, public repositories, or frontend source code that other people can inspect.

2. Existing Backend Endpoints

GET/health

Basic backend health information. This endpoint may be public.

GET/health/database

Database health information, according to the existing backend route.

GET/api/stocks

Reads stock data. Use the buyer API key if required by the backend.

GET/api/schedule

Reads schedule data. Use the buyer API key if required by the backend.

GET/events

Existing Server-Sent Events (SSE) route for streaming events. The deployed backend must support the configured authentication method.

This guide documents the routes specified for FILE 4. It does not prove that the deployed server is online or that every route is currently working.

3. Buyer API Key Authentication

The documented buyer API key header is X-API-Key.

GET /api/stocks
X-API-Key: YOUR_BUYER_API_KEY
Accept: application/json

For the existing SSE integration, the documented URL pattern also allows the API key in the query string: 

GET /events?apiKey=YOUR_BUYER_API_KEY
Query-string keys can appear in browser history, server logs, and monitoring systems. Prefer the request header when the endpoint and client support it. Browser-native EventSource cannot set arbitrary request headers, which is why the existing frontend may use the query parameter.

4. Example: Read Stock Data

This example performs a GET request only. It does not change backend data.

JavaScript fetch example 
async function loadStocks(backendUrl, buyerApiKey) {
  const response = await fetch(
    new URL("/api/stocks", backendUrl),
    {
      method: "GET",
      headers: {
        "Accept": "application/json",
        "X-API-Key": buyerApiKey
      },
      cache: "no-store"
    }
  );

  if (!response.ok) {
    throw new Error("Stock request failed: HTTP " + response.status);
  }

  return await response.json();
}

5. How to Get a Buyer Key

  1. Open the backend's existing buyer login/key-generation page.
  2. Sign in with the buyer account credentials provided to you.
  3. Generate or retrieve the key through the supported account workflow.
  4. Paste the key into the trusted frontend's API key field.
  5. Load stock or schedule data and review the response.

The exact login and key-generation response depends on the deployed FILE 4 implementation. This guide does not generate, reveal, or store keys.

6. Troubleshooting

HTTP 401 — Unauthorized

  • Check that you pasted the buyer key correctly.
  • Confirm that the key belongs to the correct buyer account.
  • Check whether the key has expired or been rotated.
  • Confirm that the request uses the authentication method expected by the backend.

HTTP 403 — Forbidden

  • The key may not have permission for the requested endpoint.
  • Check the backend's actual authorization rules.

HTTP 404 — Not Found

  • Check the backend base URL and route path.
  • Confirm that the deployed version includes the route.

Network error or CORS error

  • Check that the backend is reachable.
  • Confirm the deployed CORS configuration allows the frontend origin and required headers.
  • Check browser developer tools for the actual request error.

Empty stock or schedule response

  • A successful request can still return an empty dataset.
  • Inspect the raw JSON response before concluding that the bot or database is broken.
  • Do not treat schedule records as confirmed spawn events unless the returned data supports that interpretation.

7. Read-Only and Security Rules

This guide makes no backend requests automatically and contains no database writes, user-management actions, or key-generation requests.
  • Do not put Discord bot tokens or database credentials in HTML.
  • Do not commit buyer API keys to public repositories.
  • Use HTTPS when connecting to a deployed backend.
  • Do not send your buyer key to untrusted websites.
  • Use the backend's official key rotation/revocation workflow if a key is exposed.
