Steal An Egg — Backend README

Setup overview, existing API routes, buyer access and troubleshooting.

1. Project Purpose

This backend is intended to provide stock and schedule data to the Steal An Egg frontend and OBS overlay. It also supports buyer API key authentication and the configured spawn-data ingestion workflow.

Verification status: This document describes the project's specified architecture. It does not mean that the deployed backend, database, Discord integration, or every frontend connection has been tested successfully.

4. Buyer API Key Authentication

The specified buyer API uses the X-API-Key request header for protected data endpoints. 

GET /api/stocks
X-API-Key: YOUR_BUYER_API_KEY
Accept: application/json

The existing SSE integration may accept an API key through the apiKey query parameter where implemented.

Never paste a real buyer key into public HTML, screenshots, source control, or public chat. A query-string key can also appear in logs and browser history.

5. Environment and Database

Environment variable names must match the implementation and hosting configuration. The specified design includes database connection settings, admin credentials and a separate bot-ingestion secret.

  • Use the provided .env.example as a reference, not as a file containing production secrets.
  • Set real secrets in the hosting provider's environment-variable settings.
  • Do not expose database passwords, bot tokens, admin passwords or ingestion secrets to the browser.
  • Confirm the database driver and connection-variable format match the current index.js.

A configured TIDB_DATABASE_URL does not, by itself, prove that the application actually reads that variable correctly. Database connectivity must be checked against the current backend code and deployment logs.

6. Discord Spawn Data Flow

  1. The configured bot or webhook receives a supported spawn notification.
  2. The backend ingestion route validates its configured authentication.
  3. The backend stores or processes the event according to its implementation.
  4. The frontend reads stock and schedule data or connects to the existing SSE stream.

This is the intended architecture, not proof that every step currently succeeds. Do not assume every schedule record is a confirmed spawn event. The frontend should distinguish actual received spawn alerts from predicted timers.

7. Troubleshooting Checklist

Backend unavailable

  • Check the configured deployment URL.
  • Review the hosting provider's application logs.
  • Inspect the response from /health.

Database disconnected

  • Check the configured database URL or required database variables.
  • Verify database credentials and network access.
  • Review the actual database initialization error in server logs.

Buyer key rejected

  • Verify the key belongs to the intended buyer account.
  • Check key expiry, rotation and endpoint authorization.
  • Confirm the request sends the header expected by the backend.

Spawn events missing

  • Verify the bot or webhook can reach the existing ingestion route.
  • Check the ingestion secret configuration without exposing its value.
  • Review the actual event payload and server logs.
  • Check SSE reconnection behavior and the browser's network panel.

Browser connection or CORS errors

  • Check the frontend origin against the deployed CORS configuration.
  • Check whether the required request headers are allowed.
  • Remember that browser restrictions can block a request even when the server is running.
